SOUTHAMPTON REFINE — WHAT GEOCRAFT ALREADY DID
Updated: 11 October 2026 (Europe/London)

This world (Southampton2023) was generated by Geocraft
(~/Projects/geocraft), not by this refine kit. Refine edits sit on top of
that prior phase. Agents must know what to trust vs replace.

Source tree (authoritative for generator behaviour):
  generate-world
  lib/Minecraft/Projection.pm   — per-column DTM/DSM + block stack
  lib/Minecraft/VectorMap.pm    — OSM Overpass → land-use raster
  lib/Elevation/UKDEFRA.pm      — DEFRA composite DTM + DSM
  config/blocks                 — materials / hollow buildings

Offsets for this save: config/map-maker-offsets.json
  OFFSET_E=436248  OFFSET_N=109608  SEA_LEVEL=11  EXTEND_DOWNWARDS=9
  Bounds MC X 0…11604, Z −8666…0  (1:1 OSGB metres)

------------------------------------------------------------------------
1. PIPELINE (one column at a time)
------------------------------------------------------------------------
 For each Minecraft (X,Z):

 1. OSGB: E = OFFSET_E + X,  N = OFFSET_N − Z
 2. Land-use code from Minecraft::VectorMap (live OSM at generate time),
    not from painted map tiles (MapTiles path is disabled in Projection).
 3. Heights from UKDEFRA LIDAR at that lat/long:
      DTM  = ground
      DSM  = first/last-return surface (roofs, trees, …)
      elevation      = DTM
      feature_height = int(DSM − DTM)   # extruded above ground
 4. config/blocks decides materials: ground block, up_block stack,
    optional hollow interior (is_inside), carpet/roof over_block.
 5. Y placement: SEA_LEVEL(11) + DTM offset + feature stack.
    (SEA_LEVEL = 2 + EXTEND_DOWNWARDS 9.)

------------------------------------------------------------------------
2. TRUST MATRIX — use this when refining
------------------------------------------------------------------------
 TRUST (keep unless evidence contradicts):

  • Building plan outline / footprint shape — OSM closed ways +
    multipolygon relations, rasterised into the MC grid. Usually within
    ~1 block of reality for mapped buildings.
  • Road / path *route* (centreline alignment, junctions, connectivity)
    — OSM highway geometry projected to OSGB.
  • Terrain ground height and overall building *volume* height —
    LIDAR DTM and DSM−DTM. Massing authority for Y (see NOTES §5).
  • Water polygons and many landuse patches — OSM areas.
  • Absolute position — OSGB offsets above; convert with scripts/osgb.py.

 DO NOT TRUST (expect to fix from aerial / street photos):

  • Road *width* and pavement *width* — arbitrary fixed buffers from
    highway class (see §3). Kerbs following stock edges often look wrong.
  • Building materials / colour — coarse OSM tags → brick, concrete,
    church stone, etc. Not real elevations.
  • Openings — almost none. RETAIL gets fake glass bands at y_offset 2–3;
    houses are blank shells.
  • Roofs — flat (carpet / top_block); DSM height is a “pancake”, not
    pitch, hips, or chimneys.
  • Interiors — hollow air when look_around sees the same land-use on
    four sides. Not real rooms (and refine forbids private interiors).
  • Trees / vegetation clutter — procedural from feature_height on
    nature cells, not surveyed stems.
  • Tunnels / negative layer / proposed / construction highways —
    skipped at generate time.

 When aerial, OSM clip, and live blocks disagree on footprint: prefer
 measured LIDAR/aerial outline; OSM is the generator’s input, not a
 veto on better evidence (reference/SOURCES.txt priority).

------------------------------------------------------------------------
3. HOW ROADS WERE DRAWN (why width is arbitrary)
------------------------------------------------------------------------
 VectorMap.pm for each OSM highway way (non-tunnel, layer≥0):

  1. Optional pavement pass: most ordinary roads get draw_route
     PAVEMENT with width=6 (≈6 m each side of centreline → ~12 m total
     pavement envelope). Pedestrian/footway/service/motorway/… skipped.
  2. Carriageway pass: draw_route with a *fixed* half-width by class:

       default (residential, tertiary, …)  ROAD       width 4
       service                             ROAD       width 2
       footway / path / steps              PATH       width 2
       track / bridleway                   TRACK      width 3
       cycleway / pedestrian               FANCYROAD  width 2 or 4
       motorway / raceway                  FANCYROAD  width 6

     extrude(from,to, width, width) + circle caps → polygon raster.
     So a default road is ~8 m total carriageway, independent of real
     lane count or OSM width=* tags (those tags are ignored).

  Priority (SCORE): BUILDING (200) > FANCYROAD (100) > ROAD (90) >
  WATER (80) > TRACK (50) > PAVEMENT (30) > PATH (20) > grass/…
  Buildings win over roads where footprints overlap; pavement is only
  the fringe the road pass did not overwrite.

 Front gardens (I-009): the PAVEMENT fringe also covers front gardens.
 Between the pavement strip and the houses Geocraft leaves a raised stone
 band at LIDAR hedge/wall height (Broadlands Rd: ~5–7 blocks deep). It is
 gardens, not building. The house front is the OSM footprint edge
 (scripts/osm_footprints.py frontage); keep the garden between.

 Refine implication (I-006): treat stock road/pavement *edges* as a
 sketch. Keep the corridor / centreline; trim or widen to aerial +
 street evidence. Do not place kerbs on “Geocraft kerb line” without
 checking photos.

------------------------------------------------------------------------
4. HOW BUILDINGS WERE DRAWN
------------------------------------------------------------------------
 • Footprint: OSM building=* ways/relations → filled polygon (holes via
   multipolygon inners). Shape in plan is the strong signal.
 • Height: LIDAR feature_height, with feature_min_height=3 for building
   classes (short DSM bumps still get a 3-block shell).
 • Shell: stone undercroft; brick (or tag variant) walls; air inside;
   light-grey carpet (or variant) on top — not a real roof form.
   From street/air this often reads as a striped/lattice “pancake”
   of full blocks — replace with a sealed pitch (CRAFTSMANSHIP.txt).
 • Missing OSM building → no BUILDING code; LIDAR may still raise
   DEFAULT/grass columns where DSM > DTM (weird “pancakes”).

 Refine implication: keep plan shape as a guide (square ±1–2 for
 Minecraft — do not copy every OSM jag); rebuild whole properties
 (all elevations, roof, floors + stair, gardens) from photos + aerial;
 no rooms/furniture in private houses; do not fight LIDAR Y massing
 without a place-brief exception.

------------------------------------------------------------------------
5. WHAT REFINE IS FOR (vs regenerating Geocraft)
------------------------------------------------------------------------
 Do not re-run generate-world over Southampton to “fix” streets.
 Prefer local kit builds + region snaps (PROCESS §2a). Regenerate only
 if the user explicitly asks for a new Geocraft export.

 Typical refine jobs that follow from this prior phase:
  • Road width / kerb / pavement against aerial (trust route, fix width)
  • Whole properties: elevations, openings, roofs, floors, gardens
  • Roof read from aerial (still good-enough: no chimney obsession)
  • Footprint tweaks only where OSM polygon is clearly wrong vs aerial
  • Water edges / public realm furniture with evidence
