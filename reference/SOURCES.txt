REFERENCE IMAGE SOURCES — Southampton
Updated: 11 Oct 2026

Priority when sources disagree (also in README.txt):
  1. measured survey / LIDAR footprint
  2. dated photography (prefer modern, note capture date)
  3. OSM / generalised maps

Geocraft already baked (1)+(3) into Southampton2023 — trust plan shapes
and road routes; distrust fixed road widths and placeholder materials.
See site/GEOCRAFT.txt.

------------------------------------------------------------------------
A. University of Southampton aerial tiles (local, convenient)
------------------------------------------------------------------------
Base:  https://tiles.maps.southampton.ac.uk/aer/{z}/{x}/{y}.png
Viewer: https://maps.southampton.ac.uk/
Example (z19): https://tiles.maps.southampton.ac.uk/aer/19/260108/175669.png

IMPORTANT — zoom levels are NOT the same dataset scaled up:

  Zoom ≤18   Hampshire Hub orthophoto (same family as the Hampshire Data
             Portal 25cm aerial). City-wide working layer for footprint /
             roof reading. Open Government Licence (OGL) — same terms as
             http://hampshire.geodata.soton.ac.uk/

  Zoom 19    Channel Coastal Observatory (CCO) tiles.
             Higher resolution, but:
               - thinner geographic coverage
               - more oblique / angled (especially over the river)
             Prefer for dockside / waterfront detail where coverage exists;
             do not assume z19 is “just sharper z18”.
             Licence: confirm CCO / maps.southampton.ac.uk attribution
             before redistributing z19 tiles.

Tile scheme appears to be standard web-mercator XYZ (confirm against a
known OSGB point before relying on x/y maths). Hotlink / Referer rules may
apply; fetch from a browser session or with an appropriate Referer if
scripting downloads.

For scripted crops: prefer z18 (Hampshire Hub / OGL) for general work;
use z19 only where the extra CCO detail is worth the angle/coverage trade-off.

Stitch mosaics (one image per place, not a pile of tiles):
  python3 scripts/aerial_mosaic.py --wm 18/x/y --place ID --dir aerial/<slug> [--add]
  python3 scripts/aerial_mosaic.py --at X,Z --zoom 18 --place ID --dir aerial/<slug>

C. Ground / street façades
------------------------------------------------------------------------
Geograph Britain & Ireland (CC BY-SA, OS grid keyed)
  https://www.geograph.org.uk/
  Dense around Civic / Old Town (e.g. SU4112, SU4111).
  Agent can fetch pages / keep attributed crops for local reference.

Mapillary (street sequences; Graph API + tiles)
  https://www.mapillary.com/
  https://www.mapillary.com/developer
  Needs a free access token (none in this project yet). With a token the
  agent can list images by bbox and download for attributed local use.
  Best programmatic street-level option.

KartaView (ex-OpenStreetCam) — similar open crowdsourced street imagery
  https://kartaview.org/
  API (no project token needed): https://api.openstreetcam.org/2.0/photo/
    ?lat=&lng=&radius=&join=sequence
  Q-002 (11 Oct 2026): good coverage on Portswood × Broadlands and
  Grosvenor/Kitchener approaches — used as primary durable façades.

Own phone photos — best for “exact façade today”.

Rightmove sold prices / listings (per postcode)
  Example: https://www.rightmove.co.uk/house-prices/so17-3sf.html
  (~44 sold records for SO17 3SF — Kitchener Rd, Grosvenor Rd, etc.)
  Use: exterior / street-facing listing photos and rough address pins for
  façade materials, bay windows, storey count.
  Do NOT use: interior galleries, floorplans, or garden shots as modelling
  targets (private interiors rule — LOGGING.txt §6).
  Licence: commercial site; look in-browser for reference. Do not bulk-
  scrape or commit listing images to the public repo without checking
  Rightmove terms. Prefer own photos or Geograph/Mapillary for anything
  we keep on disk long-term. Manifest source tag: rightmove.

Zoopla / OnTheMarket — same pattern (exteriors only; look-don't-hoard).

Google Street View
  Browser: agent can open Maps / Street View and look (cookie consent).
  API: Street View Static API needs Google Cloud billing + API key; ToS
  generally forbid caching/storing imagery (look / ephemeral use only).
  No Google Maps key in this environment today.
  Verdict: fine for interactive inspection; poor as a project archive.
  Fixed-URL look (no key, found 2026-10-14, Q-072): open in the built-in browser
    1. https://www.google.com/maps/@?api=1&map_action=pano&viewpoint=<lat>,<lon>&heading=<deg>
       (lat/lon from the MC xz: osgb.to_osgb + gdaltransform EPSG:27700->4326; reject
       cookies on the consent page). Wait ~4s; the final URL carries the nearest pano id
       (!1s<panoid>) and its capture date (shown bottom right).
    2. https://streetviewpixels-pa.clients6.google.com/v1/thumbnail?cb_client=maps_sv.tactile
       &w=900&h=600&pitch=0&panoid=<panoid>&yaw=<deg>   -> a plain image per heading, so
       several yaws from one pano are cheap. Unofficial endpoint: may change or be limited.
  SINGLE STEP (found 2026-10-14): the same thumbnail URL accepts `&ll=<lat>,<lon>` in place
    of `&panoid=` and returns the nearest pano's image directly (no Maps page, no pano id).
    Just open  .../v1/thumbnail?cb_client=maps_sv.tactile&w=900&h=600&pitch=0&yaw=<deg>&ll=<lat>,<lon>
    in the built-in browser and look. (`lat=`/`lng=`/`location=` are rejected, 400.) curl needs
    a google.com Referer; the browser pane does not. Image varies with ll, so it is honoured.
    Caveat: it does not tell you the pano id/capture date, so use the two-step method when
    you need to cite them. Vary yaw for each wall; move ll along the street for other angles.
  SAVING (user decision 2026-10-14): kept frames MAY be saved locally via
    scripts/streetview_sample.py keep -> reference/photos/streetview/<cell>/ (gitignored,
    logged in manifest.jsonl). Never commit the images; keep it to frames chosen from a
    small per-cell sample, not bulk harvesting.
  Otherwise look only: view it, write down what it shows (materials, storeys, entrances) in the
  cell SOURCES / script docstring. Do NOT download, commit or hash the images, and do not
  loop it over many panos (ToS). Log the pano id + capture date as the citation.

Google satellite tiles (ALWAYS look, every cell; added 2026-10-16, user)
  Often clearer than the university aerial (sharp, current, roof detail and wall colour visible).
  Plain tile URL, no key, same unofficial/look-only status as the Street View thumbnails:
    https://mt1.google.com/vt/lyrs=s&x=<x>&y=<y>&z=<z>      (lyrs=y adds road labels)
  x/y/z are web-mercator tile numbers, the same scheme as the uni tiles (z18 x=130056 y=87838 is Oakdene).
  z19 tile ~48 blocks, z20 ~24 blocks. Do not use the tile URL by hand; use the sheet:
    python3 scripts/google_aerial.py sheet --cell TX,TZ            # whole cell at z19, MC grid every 10 blocks
    python3 scripts/google_aerial.py sheet --at X,Z [--radius 30]  # a building at z20
    add --outlines to draw the OSM building outlines (red, way-id tail in yellow) so each building compares at a glance;
    the file is then <name>_osm.html. Review chats (site/GOOGLE-REVIEW.txt, I-073) are queued automatically by
    site_handoff.py next; end one with: site_handoff.py end Q-nnn --review-status look|features|done (default done).
  It writes instance/google-aerial/<name>.html; open it as file://... in the built-in browser. Tiles load from Google
  in the browser; nothing is downloaded. Look, write what it shows (roof, materials, footprint, trees) in the cell
  SOURCES / script docstring, then record it:
    python3 scripts/cell_sources.py --cell TX,TZ --record google --result found --note "..."
  Repeat looks (another building in the same cell) need no retry reason. Never save, hash or commit the tiles and
  never loop it over many cells (ToS). If a build needs a kept image, the user adds a screenshot to
  reference/aerial/highfield-user/ as before. Aerial lean: a tall roof sits a few blocks off its ground footprint.

F. University building entrances ("portals") — door positions + photos
------------------------------------------------------------------------
Register:  https://maps.southampton.ac.uk/data/portals.json   (added 2026-10-16, user)
Stored:    reference/portals/portals.json  (committed; normalised, coordinates in OSGB and Minecraft X/Z)
Tool:      python3 scripts/portals.py  (fetch | info | cell tx,tz | bbox | building N | near x,z)
  285 entrances of 152 university buildings (273 inside the Geocraft map; the rest are Winchester / other sites).
  Each row: id (building-letter, e.g. 42-A), building number, label ("Main", "Concourse entrance"), lat/lon of the
  ENTRANCE (not the photo), and 0+ photo URLs on data.southampton.ac.uk (80 portals have one). The register repeats a
  row per photo; the store merges them into `images`.
  Trust: positions sit on the building wall (median 0.5 blocks from the OSM footprint, 103 of 114 within 6). Use them
  for WHERE a door goes and what it is called; the photo says what it looks like. Not every door is listed (no
  private or staff-only doors, few small buildings), so a missing portal is not evidence of no door.
  Photos: the register's links are 200 px thumbnails; the archive also serves 400/600/800/1000/1600 px (swap the number
  in the URL; portals.photos() does it). Work at 800 px (~45 KB, signs and glazing legible); 1600 only for a detail.
  Saved locally (user, 2026-10-16): python3 scripts/portals.py download -> reference/photos/portals/<id>.jpg at 800 px
  (86 files, gitignored, each logged in manifest.jsonl). Look at those, not the URLs. Otherwise look-only like Street View (open the URL in the browser pane, write down what it shows). Do not bulk-download.
  Feature builds: cell_features.missing_features and the queue item list a feature's portals; Campus(..., portals=True)
  puts a door at each one. See site/CRAFTSMANSHIP.txt "ENTRANCES".

G. Tree Preservation Orders (protected trees only)
------------------------------------------------------------------------
Council page (look-up UI, not authoritative geometry):
  https://www.southampton.gov.uk/environment/trees-grass-hedges/protected/tpo-map/

Reverse-engineered (Oct 2026): that page embeds ArcGIS Experience
  https://experience.arcgis.com/experience/c0ad4ce95f8e46cfb28bb8cb126eaec0
  owned by Wigan Borough Council (layers under services.arcgis.com/Uk58AEewwvNNTAX2).
  Do not use that map for Southampton coordinates — use the feeds below.

Authoritative Southampton feeds (planning.data.gov.uk register):
  Trees (points): WFS Data:TPOS_TREES_DATA_EXT
  TPO zones:      WFS Data:TPOS_DATA_EXT
  Base URL pattern:
    https://www.southampton.gov.uk/geoserver/Data/ows?service=WFS&version=1.0.0
    &request=GetFeature&typeName=Data%3ATPOS_TREES_DATA_EXT&outputFormat=csv
    &srsName=EPSG:4326
  GeoServer may return Incapsula HTML to datacentre IPs; bulk CSV works without that.

National mirror (OGL, filter organisation-entity 318 = Southampton):
  https://files.planning.data.gov.uk/dataset/tree.csv
  ~4494 tree points; tree-species column is empty for Southampton as of Oct 2026.
  Species live in TPO PDF schedules (modernGov) or may appear in local WFS columns —
  track overrides in reference/tpo/species-overrides.jsonl.

Project tool:
  python3 scripts/tpo_fetch.py --warm-cache          # once: download + index
  python3 scripts/tpo_fetch.py --at X,Z --radius-m 250 --place ID
  python3 scripts/tpo_fetch.py --bbox-mc x0,z0,x1,z1 --out reference/tpo/….geojson
  Local cache (gitignored): reference/tpo/cache/planning-tree.csv +
  southampton-trees.jsonl (~4.5k rows, fast bbox queries). Refresh weekly or
  --refresh-cache after planning.data updates.

Geocraft builds: TPO trees are legally protected individuals, not every garden
tree. Placement for ordinary plots still comes from aerial; use TPO data to avoid
removing protected trees and to label species when known.
